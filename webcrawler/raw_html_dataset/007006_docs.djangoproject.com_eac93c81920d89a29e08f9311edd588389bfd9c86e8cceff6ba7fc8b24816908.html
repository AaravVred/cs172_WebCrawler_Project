Glossario¶

modello reale¶

Un modello non astratto (abstract=False).

campo¶

Un attributo di un a model; un determinato campo di solito viene associato direttamente ad una singola colonna del database.

Vedi Models.

vista generica¶

Una funzione di view di ordine superiore che fornisce un’implementazione astratta/generica di un idioma o schema diffuso nello sviluppo vista.

Vedi Class-based views.

modello¶

I modelli memorizzano i dati della tua applicazione.

Vedi Models.

MTV¶

«Model-template-view»; un modello software, simile a MVC, che descrive però in modo migliore il funzionamento di Django.

Vedi voce FAQ.

MVC¶

Model-view-controller; un modello software. Django segue in qualche misura MVC.

progetto¶

Un pacchetto Python, ovvero una directory del codice, che contiene tutte le impostazioni relative ad un’istanza Django. Questo include la configurazione del database, le opzioni specifiche di Django e le impostazioni relative all’applicazione.

proprietà¶

Anche conosciuta con il nome di «attributi gestiti», e una funzionalità di Python integrata a partire dalla versione 2.2. È un buon modo per implementare attributi, che assomiglia nel suo uso all’accesso attributi, ma la quale implementazione si serve di invocazioni di un metodo.

Vedi :classe:”proprietà”.

queryset¶

Un oggetto che rappressenta un insieme di linee da estrarre dal database.

Vedi Making queries.

slug¶

Una breve etichetta che identifica un oggetto e che contiene solo caratteri alfanumerici, trattini bassi o trattini d’unione. Sono generalmente utilizzate negli URLs. Per esempio in un tipico URL di un articolo di blog:

https://www.djangoproject.com/weblog/2008/apr/12/spring/

l’ultimo elemento (spring) è lo slug.

template¶

Un pezzo di testo che agisce da base di formattazione per rappresentare i dati. Un modello aiuta a estrapolare i dati dalla loro rappresentazione.

Vedi Templates.

vista¶

Una funzione responsabile del rendering di una pagina.
